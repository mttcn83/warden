# Contributing

Thanks for helping. Warden is small on purpose: keep changes focused and readable.

## Set up
```bash
git clone https://github.com/<you>/warden.git && cd warden
npm install
cp .env.example .env     # a test bot token in a test server
npm run dev
```

## Before you open a pull request
```bash
npx tsc --noEmit          # types
npx vitest run            # tests (includes the human-written validation sets)
npx tsx bench/validate-final.ts   # filter accuracy over every set
```

## Rules of the house
- **Everything is opt-in and off by default**; destructive modules (raid, guard) start in shadow mode.
- **Rules decide moderation.** There is no AI model, and none should be added.
- **Filter changes need data.** Add messages to a file in `bench/` (a harmless near-miss for every false alarm you fix, a real insult for every miss) and keep `bench/validate-final.ts` at zero mistakes. Fix the cause (a pattern, a softener), not the single message.
- **Keep the CLI in step with every feature.** See the checklist at the bottom of this file.
- Never put tokens, real user data or real people's details in tests, logs or issues.

## Checklist: keep the CLI, wizard and panel in step
Self-hosted, opt-in Discord moderation bot (TypeScript, discord.js, SQLite) with a localhost control panel (`gui/index.html`) and a dependency-free CLI (`bin/`).

Whenever you add or change a feature, check whether the command line and setup wizard need updating **in the same change**:

- **New module or setting group with an `enabled` switch** (like `filter`, `spam`, `raid`, `guard`): give it an explicit decision in every preset in `bin/presets.js` (what the wizard switches on, and whether it starts in shadow mode). A test (`src/core/presets.test.ts`) fails if a module is missing.
- **New module, category or setting a new user should choose:** also add the question to `bin/features.js` (the Full walkthrough) with a plain-language explanation, and keep the warnings in `bin/wizard.js` (`alwaysOnWarnings`) accurate.
- **New permission the bot needs, or a new intent:** update `bin/discord.js` (`RECOMMENDED`, `RECOMMENDED_NAMES`, `intentsFromFlags`) and the checks in `bin/wizard.js` (`doctorCommand`, intents step).
- **New environment variable, file or setup requirement:** update the wizard (`bin/wizard.js`), `warden --doctor`, `.env.example` and the README.
- **Bot look:** the default picture is `assets/warden-avatar.png` (source: `assets/warden-avatar.svg`, the panel logo on its dark background, rendered with `rsvg-convert -w 1024 -h 1024`). The banner is `assets/warden-banner.jpg` (generated by `assets/make-banner.py`, 1360x480). The wizard and `warden --profile` share `bin/look.js`.
- **Feedback:** the panel button and `warden --feedback` share `bin/feedback.js`; anything new that can contain secrets must be covered by `redact()` and its test (`src/core/feedback.test.ts`).
- **Mod log / activity:** the private channel (`createModLogChannel` in `src/core/actions.ts`, `bin/modlog.js`, `warden --logchannel`) and the Logs tab / `warden --activity` read the same audit table. New automated actions should write an audit row; ones moderators must know about should also post to the mod log (never repeat personal information or leave a link clickable: use `removalNotice`).
- **Raid detection invariants** (tested in `src/modules/raid/detect.test.ts` and `src/sim`): each account counts once however often it rejoins (Kevin), established accounts with a picture weigh a quarter and are let through, slow raids need several signals together (never one odd trait), and every message from a recognised raider is deleted. Change the signals in `detector.ts`, not by lowering thresholds.
- **New CLI command or flag:** add it to `bin/commands.js` (drives `--help`) and `bin/warden.js`, and document it in the README command table. A test fails if the README is missing a command.
- **Anything that changes first-run or setup:** walk through `warden --setup` and `warden --doctor` yourself and fix what is stale.
- Update the README feature list and the control panel (`gui/index.html`) for user-facing features too.

## Other conventions
- Everything is opt-in and off by default; destructive modules (raid, guard) start in shadow mode.
- Rules (`src/rules`) decide moderation. There is no AI model: it was removed on purpose (it could be fooled by gentle wording and cost a 130 MB download). Do not add one back.
- The raid engine and admin guard run the same code for the real bot and the attack simulation (`src/sim`); keep it that way.
- Run `npx tsc --noEmit` and `npx vitest run` before finishing.
